# montazh-lite: чистка ролика с говорящей головой

**TL;DR:** Вход: сырой ролик, где человек говорит в камеру. Выход: чистый mp4 (паузы вырезаны, звук −16 LUFS, зум на швах) и отчёт `check.py` с PASS/FAIL по числам. Работает на ffmpeg и стандартной библиотеке Python, без платных сервисов, ключей и скачиваний. Субтитры, анимацию и эффекты делает второй скилл: этот только готовит ролик под них. Две остановки человека: первый прогон на куске 15 секунд и готовый ролик.

`<SKILL>` ниже — папка этого скилла (где лежит этот файл). Работай из папки с роликом человека. Команды написаны для bash; на Windows запускай их в Git Bash или PowerShell (замени `python` на `py`, если `python` не найден).

**Запускай скрипты как список аргументов инструментом, а не строкой оболочки; файл с одиночной кавычкой в имени сначала переименуй копией.** Команды в блоках ниже даны как справочные примеры: путь в них стоит в одинарных кавычках.

## Что уходит из компьютера — скажи человеку одной фразой до начала

- Скрипты ничего не отправляют и ничего не скачивают: резка и звук идут локально.
- Но ты, Claude, смотришь 1-2 кадра ролика, чтобы найти лицо для зума. Кадры уходят в модель по правилам подписки человека. Спроси «можно посмотреть кадр из вашего видео?» и без «да» не открывай.

## Как говорить с человеком

- Коротко: до 10 строк. Сверху одна строка: что готово и что от него нужно. Числа проверок — в отчёт, человеку «проверил, всё в норме» и 2-3 главных цифры (длина было → стало).
- Без жаргона: «зум на швах» → «каждый второй кусок чуть крупнее, чтобы склейки не бросались в глаза»; LUFS → «громкость как на YouTube»; «шов» → «место склейки».
- Один вопрос за раз, с объяснением, что будет при каждом ответе.
- Файлы человека не трогай и не удаляй: результат кладётся рядом под именем `<имя>-montazh.mp4`.
- Слушать звук ты не можешь. Всегда скажи: «громкость проверил числами, а как звучит, послушайте сами».
- Если человек просит субтитры, анимацию или эффекты: скажи, что это делает второй скилл, и не делай.

## Безопасность имён файлов (обязательно)

Имя файла человека может содержать символы, которые оболочка исполнит как команду (в двойных кавычках bash выполняет `$(...)` и обратные кавычки). Поэтому:
- Запускай скрипты как список аргументов инструментом, а не строкой оболочки; файл с одиночной кавычкой в имени сначала переименуй копией.
- Путь к файлу передавай только отдельным аргументом **в одинарных кавычках** (`'./ролик.mp4'`), в bash и в PowerShell. В примерах ниже так и сделано; двойные кавычки для файлов человека не используй.
- Перед запуском проверь имя файла. Если в нём есть любой из символов `$` `` ` `` `"` `'` `;` `|` `&` `<` `>` `\n` (перевод строки), **не запускай команду**: скажи человеку «в имени файла есть символ, который опасен для командной строки» и предложи переименовать файл (или сделай копию с простым именем после его «да»). Имя, начинающееся с `-`, передавай как `'./имя'`.
- Результат всегда называй сам: `<простое-имя>-montazh.mp4`, а не по имени из файла.
- Последние строки `montazh.py` с путями (`Check: run check.py with these arguments`) в оболочку не вставляй: там нет готовой командной строки специально. Проверку запускай сама командой из шагов 3 и 4 (`python '<SKILL>/scripts/check.py' './результат.mp4'`), путь отдельным аргументом в одинарных кавычках.
- Скрипты не пишут через символические ссылки и не затирают исходник и готовый результат (нужен `--force`); отказ приходит кодом 2 с понятной строкой, ссылку не обходи.

## Порядок работы

Запускай скрипты как список аргументов инструментом, а не строкой оболочки; файл с одиночной кавычкой в имени сначала переименуй копией. (Одинарные кавычки в примерах ниже нужны только на случай, если команду всё-таки приходится запускать через оболочку.)

### Шаг 1. Окружение

Сначала проверь Python (без него скрипты не запустятся, в том числе `doctor`). Попробуй по очереди, пока одна команда не ответит версией:
```bash
python --version
python3 --version
py --version
```
Нужен Python 3.10 или новее. **Если Python нет или он старее 3.10:** предложи поставить и поставь только после «да»: Windows `winget install Python.Python.3.12`, Mac `brew install python`, Linux `sudo apt install python3`; потом перезапустить терминал и повторить проверку. Дальше в командах пиши ту форму, которая ответила (`python`, `python3` или `py`).

Потом проверь остальное:
```bash
python '<SKILL>/scripts/montazh.py' doctor
```
Нужна последняя строка `ALL OK` (ffmpeg и ffprobe с кодировщиками H.264 и AAC и звуковыми фильтрами, Python 3.10+). Если ffmpeg нет или в нём не хватает кодировщиков (doctor напишет, чего именно), предложи поставить полную сборку и поставь только после «да»: Windows `winget install Gyan.FFmpeg`, Mac `brew install ffmpeg`, Linux `sudo apt install ffmpeg`, потом перезапустить терминал. Больше ничего ставить не надо.

### Шаг 2. Лицо в кадре (для наведения зума)

Сними кадр из середины ролика (ещё один из конца, если человек двигается). Команда сама берёт кадр по доле длины ролика, на коротких клипах тоже работает:
```bash
python '<SKILL>/scripts/montazh.py' frame './ролик.mp4' --out frame.jpg --at 0.5
python '<SKILL>/scripts/montazh.py' frame './ролик.mp4' --out frame2.jpg --at 0.9
```
Открой кадр и оцени прямоугольник лица вместе с шапкой и подбородком как доли кадра: `левый,верх,правый,низ`. Для человека по центру это что-то вроде `0.40,0.08,0.60,0.46`. Бери с запасом по ширине, если человек двигается между кадрами (объединение). Зум наводится на центр этого прямоугольника, `check.py` проверяет, что лицо не вышло за край увеличенного кадра.

### Шаг 3. Первый прогон на куске 15 секунд

```bash
python '<SKILL>/scripts/montazh.py' run './ролик.mp4' --out out/test15.mp4 --face-box L,T,R,B --start 0 --end 15
python '<SKILL>/scripts/check.py' out/test15.mp4
```
Покажи человеку `out/test15.mp4` (полный путь одной строкой) и спроси: «Паузы и зум подходят? Что поправить?» Правки вкуса: раздел «Вкус».

### Шаг 4. Весь ролик

```bash
python '<SKILL>/scripts/montazh.py' run './ролик.mp4' --out './ролик-montazh.mp4' --face-box L,T,R,B
python '<SKILL>/scripts/check.py' './ролик-montazh.mp4'
```
`check.py` должен закончить строкой `ALL PASS`; если в ней есть пометка `not measured: zoom`, значит проверка зума не выполнялась (не задан `--face-box`): повтори прогон с `--face-box` и покажи человеку только после этого. Если есть FAIL, чини причину и перезапускай; не показывай человеку ролик с красной проверкой. Что проверяется: громкость (−16 LUFS ±0,5, пик не выше −1 dBTP); самая длинная тишина в речи; нет повторных и пустых кадров на склейках; картинка и звук одной длины; лицо не вышло за край увеличенного кадра. «Принимаю» от человека замораживает файл: правка выходит новым файлом `…-v2`.

## Какие файлы принимает и что выдаёт

- Вход: файл с видео и звуком, который читает ffmpeg и по которому ffprobe отдаёт частоту кадров и длительность (mp4, mov, mkv, webm и т. п.). Без звука, без видео или без этих двух чисел скилл откажется.
- Выход: всегда mp4 (видео H.264, звук AAC), размер как у исходника (шире 1920 пикселей уменьшается до 1920). Частота кадров берётся номинальная из файла: у записей с переменной частотой (часто экран и телефон) настоящая частота может отличаться, и на выходе она станет постоянной.
- Куда пишет: только в `--out` и `--out.plan.json` рядом. Не пишет через ссылки (в том числе если ссылкой является папка; для доверенной папки есть флаг `--allow-linked-folders`; на Mac `/tmp` и `/var` как раз ссылки).

## Что делает каждый шаг (чтобы объяснять и настраивать)

| Что | Как | Ручки |
|---|---|---|
| Паузы | Порог тишины считается по шуму самого файла (5-й перцентиль +20 дБ, от −52 до −36 дБ). Тишина от `--min-pause` ужимается до `--keep-gap`, лишнее в начале и конце срезается. Резы по границам кадров. | `--min-pause 0.45`, `--keep-gap 0.20` |
| Звук | Фильтр гула 70 Гц, лёгкое шумоподавление (`afftdn`), короткие плавные стыки 6 мс (нет щелчков), громкость двумя проходами (`loudnorm`). | `--lufs -16`, `--tp -2`, `--denoise off/light/strong` |
| Зум | Каждый второй кусок кадрируется крупнее и наводится на лицо. Куски короче 0,7 с не меняют масштаб. | `--zoom 1.12` (1.0 = без зума) |

## Вкус: как учить скилл

Человек говорит словами, ты переводишь в числа и записываешь в `taste.json` в папке проекта (скилл читает его сам, ключи командной строки сильнее файла):

| Человек говорит | Меняй |
|---|---|
| «паузы режет слишком резко» | `min_pause` 0.45 → 0.6, `keep_gap` 0.20 → 0.30 |
| «слишком рубленый, дёрганый» | `zoom` 1.12 → 1.06 или 1.0 |
| «зум бросается в глаза» | `zoom` 1.06 |
| «звук в ушах шумит / глухой» | `denoise` off ↔ light ↔ strong |
| «тише/громче» | `lufs` −16 → −18 / −14 |

Пример: `{"min_pause": 0.6, "keep_gap": 0.3, "zoom": 1.06}`. Подробности: `references/taste.md`.

## Чего скилл не делает

- Не накладывает субтитры, анимацию и эффекты: это второй скилл. Этот только готовит чистый ролик.
- Не следит за взглядом и морганием на склейках: на стыке может мелькнуть закрытый глаз. Если человек заметил, подними `--min-pause` или поправь резы руками.
- Не ищет и не убирает дубли и оговорки по смыслу; режет только тишину.
- Слух не проверяет (только числа). Вертикальная съёмка, HDR и 10 бит: не проверялись.

## Ошибки

| Симптом | Что делать |
|---|---|
| `ffmpeg not found` | Шаг 1. Поставь ffmpeg и перезапусти терминал. |
| `no speech found` | Звук слишком тихий или выбран не тот отрезок. Проверь `--start/--end`. |
| `FAIL pauses` | Порог тишины не поймал шум: подними `--min-pause` или включи `--denoise strong` и повтори. |
| `FAIL zoom` | Зум обрезал рамку лица: уменьши `--zoom` или пересчитай `--face-box`. |
